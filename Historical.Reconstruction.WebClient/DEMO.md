# Демоверсия для GitHub Pages

Демо работает без API и базы. Все примеры условные; иллюстрации созданы для макета.
Созданные через форму записи хранятся в памяти вкладки и исчезают после обновления.

## Локальный запуск

Из папки Historical.Reconstruction.WebClient:

```powershell
npm ci
npm run dev:demo
```

Открой адрес, напечатанный Vite, с путём /Historical.Reconstruction/.

Проверка готовой сборки:

```powershell
npm run build:demo
npm run preview:demo
```

Обычные npm run dev и npm run build используют настоящий API.

## Публикация из ветки test1

1. Закоммить изменения и отправь ветку test1 на GitHub.
2. В репозитории открой Settings → Pages → Build and deployment → Source: GitHub Actions.
3. Открой Actions → Publish demo to GitHub Pages → Run workflow.
4. Выбери ветку test1 и запусти workflow. Если workflow ещё не отображается, GitHub требует файл workflow в default-ветке: перенеси туда только .github/workflows/deploy-demo.yml, затем выбери test1 при запуске.
5. После успешного выполнения открой ссылку из deployment:
   https://mikhailkrovikov.github.io/Historical.Reconstruction/

Workflow запускается только вручную: обычный push ничего не публикует.
Если репозиторий приватный, доступность Pages зависит от тарифа GitHub.

Публикуется только WebClient/dist, не API, база или папка серверных загрузок.
При переименовании репозитория обнови base в vite.config.ts.

## Проверка перед показом

- Каталог, следующая страница, поиск и выпадающие фильтры.
- Карточка находки, её картинка, возврат в каталог.
- Обновление страницы карточки (маршруты demo используют #).
- Создание записи: выбери регион, категорию и заполни поля.
- Обновление страницы сбрасывает добавленные записи.

Существующие фильтры каталога применяются к текущей странице, как и при работе с API.
Загрузка изображений поддержана на уровне demo API, но отдельной формы загрузки в текущей карточке нет.
